Every few years, a new note-taking startup promises to organize your entire brain forever. Five years later, that startup pivots toward enterprise teams, moves basic features behind a subscription tier, alters its database schema, or shuts down its servers, leaving an export button that outputs broken HTML or unreadable JSON.

Apps are temporary. Your thinking should outlast them.

That principle sits at the core of **"File over app"**, a digital philosophy popularized by [Steph Ango](https://stephango.com/file-over-app), CEO of Obsidian. Its premise is direct: ==if you want your writing to outlive the software you compose it in, the files must come first==.

> If you want to be able to read your writing on a computer in the 2060s or 2160s, it helps if your files are simple enough to have been read on a computer in the 1960s.

Plain text is the closest equivalent computing has to archival cotton paper.

## Why proprietary vaults fail the 20-year test

Notes trapped inside a remote database or binary blob depend on four fragile conditions holding true for decades: the company must stay solvent, future app versions must preserve old schemas, your login and two-factor device must keep working, and the exporter must preserve structure when you leave.

Even well-intentioned cloud tools stumble on that final step. Block-based editors serialize paragraphs into deeply nested UUID trees that flatten poorly into plain text, while proprietary rich-text formats require custom parsers just to extract a nested checklist or blockquote.

1. Vendor solvency forces you to bet your personal archive on a startup's business model.
2. Schema changes break backward compatibility when companies ship new editor versions.
3. Account lockouts or expired billing cards can cut off access to your own drafts.
4. Lossy exporters strip headings, checklists, highlights, and folder hierarchy during migration.

## The anatomy of a portable Markdown note

Markdown outlives proprietary formats because every `.md` file is readable both as raw plain text and as structured markup. Open an exported note in TextEdit, VS Code, Vim, Obsidian, Bear, iA Writer, or a terminal `cat` command forty years from now, and every heading, emphasis mark, and checklist stays legible.

When Fold serializes a note for export, it avoids wrapping prose in custom JSON schemas and writes CommonMark / GitHub Flavored Markdown paired with standard YAML frontmatter:

```markdown title="hardware-grade-local-notes.md"
---
title: "Hardware-grade local notes"
date: 2026-11-05
folder: "Ideas"
tag: "notes"
starred: true
pinned: false
---

# Hardware-grade local notes

Fold is built around **concentric double-framing**, specular reflections, and pure local persistence.

- [x] Concentric radius law: R_inner = R_outer - Padding
- [x] Directional specular catchlights on top edges
- [ ] Export complete vault archive as portable Markdown
```

Every piece of document metadata (title, date, folder, tag, and status flags) lives at the top of the plain-text file in a convention shared across modern writing tools and static site generators.

## Bridging browser speed and file longevity

Browsers restrict web tabs from reading and writing arbitrary folders on your desktop hard drive without repeated permission prompts. Fold solves this by running `IndexedDB` (`fold_db`) for sub-millisecond in-browser indexing while treating two-way Markdown and JSON portability as a primary workflow rather than a buried settings link.

Every export and import path runs locally inside your browser with zero server involvement:

| Capability | How Fold Implements Portability | Interoperability Target |
| --- | --- | --- |
| Single Note Copy | Converts editor state directly to Markdown on clipboard | Paste cleanly into GitHub, Linear, or email |
| Individual `.md` Export | Downloads `<sanitized-title>.md` with YAML frontmatter | Any plain-text editor, Obsidian, or iA Writer |
| Foldered `.zip` Vault | Assembles folder subdirectories (`Inbox/`, `Ideas/`, `Work/`, `Journal/`) via client-side `JSZip` | Drop-in archive for desktop vaults and Git repos |
| Lossless `.json` Snapshot | Exports full `Note` schema plus embeds `fold-vault-manifest.json` inside ZIP exports | One-click full-fidelity restoration back into Fold |
| Drag-and-Drop Import | Parses incoming `.md`, `.txt`, and `.json` files back into TipTap headings and tasks | Direct migration into Fold from existing folders |

## Building a long-term archive habit

Keeping control of your notes over decades takes only a simple export routine outside browser cache. Saving periodic `.zip` Markdown archives or `.json` snapshots to a local drive and opening one file in a plain-text editor each quarter confirms your writing stays independent of any single app.

- [x] Prefer tools that export human-readable `.md` files with open YAML metadata
- [x] Store periodic `.zip` vault snapshots outside browser cache (such as a local `Documents/` folder, an encrypted drive, or Time Machine)
- [x] Open an exported note in an unrelated plain-text editor once a quarter to confirm readability

When your notes open with zero proprietary runtime and move in or out of your workspace in seconds, you no longer have to wonder whether your current editor will still exist ten years from now. The files belong to you, and the application earns its place on your screen each day.
